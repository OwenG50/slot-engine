# ButchEm in Slot Engine Panel

From the repository root:

```powershell
pnpm install
pnpm --filter butch-em build
pnpm --filter butch-em run audit
pnpm --filter butch-em panel
```

Open **http://localhost:7770**, then choose **ButchEm**. Keep the terminal
running; Ctrl+C stops it. The panel uses its default port 7770, so stop another
panel instance first if that port is already occupied.

This entry point loads only ButchEm. It uses the published Panel 0.2.2 package,
which depends on Core 0.3.2, matching this game. You do not need to build the
older workspace panel or launch `examples/panel`.

## Things to try

1. **Statistics:** inspect RTP, nonzero hits, payout distributions, and mode
   costs after a normal command-line build.
2. **Book explorer:** select a mode, filter by payout or tags, and inspect the
   recorded JSON events. Try `bonusTier=hidden` or a winning symbol tag.
   A book includes every reveal, cluster award, movement, and upgrade.
3. **Reel editor:** open a generated `reels_<mode>-<profile>.csv` strip.
   For example, `reels_base-base_standard.csv` drives ordinary base candidates.
   The `bonus_` strips drive free spins and featureSpin. Dense/tail/maxwin
   variants supply the higher payout buckets.
4. **Simulation:** configure runs for the modes you want, concurrency, and
   optionally uncompressed books. Start with 1,000 rounds per mode while
   experimenting; the CLI default is 25,000.

The panel displays math data and JSON books. It is not the animated ButchEm
frontend, so roaming animation and symbol appearance changes still belong in
your game client.

The weighted payout chart uses Panel 0.2.2's built-in ranges. For a finer
breakdown like a live-game statistics site, run:

```powershell
pnpm --filter butch-em payouts
pnpm --filter butch-em payouts -- extraChance
pnpm --filter butch-em payouts -- extraChance --raw
```

The command prints the table and writes Markdown and CSV copies to
`__build__/payout-ranges-<mode>.md` and `.csv`. By default, ranges are divided
by the mode cost; pass `--raw` to use the same base-stake multipliers as Panel
and write `-raw` files. Probabilities and odds use the optimized lookup-table
weights, so run it after `build` or `optimize`.

## Reading the panel statistics

Panel 0.2.2 displays the engine's numeric units directly:

| Panel field                 | How to read it                                            |
| --------------------------- | --------------------------------------------------------- |
| RTP                         | `0.96` means 96%                                          |
| Non-zero Hit Rate           | `5` means one in five rounds, or 20%                      |
| Max Win Hit Rate            | One in N rounds                                           |
| Null Hit Rate               | `0.8` means 80% zero-pay rounds                           |
| Payout < Bet Hit Rate       | Fraction of rounds paying less than the mode cost         |
| Average/Minimum/Maximum Win | Multiples of the base stake, before dividing by mode cost |

The below-cost targets are 90% for both Extra Chance modes, 80% for Feature
Spin, 75% for Bonus, 80% for Super Bonus, and 83.5% for Hidden Bonus. Base is
unconstrained. A payout equal to cost counts as cost recovery, not below cost.
Increasing the below-cost rate reduces how often a round recovers its cost.

For percentages and bonus-tier frequencies together, use
[CALIBRATION.md](CALIBRATION.md), generated by `pnpm --filter butch-em run audit`.

## After running a simulation in the GUI

Panel 0.2.2 runs **simulation and analysis**, but does not apply this game's
optimizer targets. Newly simulated candidates have raw sampling weights.
Their RTP and bonus frequencies are not the intended player distribution.

Wait for the GUI simulation to finish, then run:

```powershell
pnpm --filter butch-em optimize
pnpm --filter butch-em run audit
```

Refresh the panel to inspect the optimized statistics. The optimizer command
expects artifacts for all seven modes; run a full `build` once before
experimenting with individual modes in the GUI.

Avoid starting CLI and GUI simulations at the same time because they write
the same output files. The native `build` command already performs all three
stages, so a separate optimizer run is unnecessary after a CLI build.

## Reel edits and local configuration

Generated reels are real inputs to the board service. Saving a reel in the
GUI changes candidate generation on the next simulation. Result-set ranges
and optimizer targets still apply: extreme reel changes may make a target
unreachable and require adjusting the math or restoring the reel.

Reel CSVs live under `examples/ButchEm/__build__/` and are reused by the
generator. To regenerate a particular strip from `src/reels.ts`, remove that
CSV and rebuild. Keep any reel edits you want before doing so.

Panel settings are saved locally in `.panel-config.json`. The game uses
`rootDir: __dirname`, so importing it from this entry point locates the same
reels, indices, books, and statistics as a CLI build.

See the official [Panel documentation](https://slot-engine.dev/docs/panel)
and [ButchEm README](README.md) for the game flow and command reference.
